# UI 设计与全局组件规范

> 文档类型：设计规范。复核日期：2026-11-28。以 `apps/web/src/theme.css`、`style.css` 和 `components/ui/` 的实际实现为准。

## 1. 设计目标

前端采用明亮、简洁、低噪声的浅色界面。视觉重点是搜索输入、来源/适配器状态和结果内容；避免大面积深色背景、过强渐变、过度装饰和不必要的卡片嵌套。

设计参考可以借鉴 MyOnlineTools 的清晰度和轻量感，但不复制其品牌资产或具体页面。

## 2. 语义化主题

- 页面背景、面板、边框、主文字、次级文字、主操作色、危险状态和焦点状态应使用主题变量。
- 组件不得在多个页面重复硬编码同一组颜色。
- 输入框和次级文字必须满足清晰可读的对比度；禁用状态不能与普通状态混淆。
- 状态颜色用于表达成功、警告、错误等语义，不作为装饰色。

主题变量集中维护于 `apps/web/src/theme.css`；页面布局和既有基础样式位于 `apps/web/src/style.css`。调整主题时同时检查搜索页、来源管理和适配器管理。

## 3. 全局组件

从 `apps/web/src/components/ui` 统一导入基础组件：

| 组件 | 职责 |
|---|---|
| `UiButton` | 主/次/危险/幽灵按钮、尺寸、加载和块级布局 |
| `UiInput` | 单行输入、标签、提示、错误和原生属性透传；数字输入回传 number 类型 |
| `UiSelect` | 原生下拉选择、v-model 和选项插槽；保留 string/number 选项值类型 |
| `UiTextarea` | 多行输入、标签、提示和错误 |
| `UiCard` | 统一卡片容器 |
| `UiEmptyState` | 空状态 |
| `UiModal` | 弹窗容器和 footer 插槽；支持初始焦点、Tab 焦点循环、Esc 关闭和关闭后焦点恢复 |
| `UiBadge` | 状态标签 |
| `UiAlert` | 信息、成功、警告和错误提示 |

数据源和适配器管理的新增/编辑弹窗统一使用 `UiModal`，由该组件负责初始焦点、Tab 焦点循环、Esc 关闭、遮罩点击关闭和关闭后的焦点恢复。\n\n`AdminLoginPanel` 是跨管理模块复用的业务级组件，接口见 [前端组件参考](../frontend-components.md)。

## 4. 使用约定

- 页面优先组合现有基础组件，不为单个页面重复实现同类控件。
- 组件只负责通用展示和交互；API 请求、领域校验和业务状态由页面或 composable 管理。
- 输入组件优先使用 `v-model`。
- 普通按钮显式使用 `type="button"`；表单提交按钮显式使用 `type="submit"`。
- 组件不直接访问 Worker API、KV 或 localStorage。
- 组件 API 应保持稳定、类型明确，并为关键交互提供可访问名称和焦点状态。

## 5. 布局与响应式

- 搜索栏中的输入框、分类选择、模式选择和搜索按钮应在桌面端保持视觉对齐。
- 查询输入框不应无限扩张挤压其他控件。
- 小屏幕允许换行或纵向堆叠，但操作顺序和标签必须清晰。
- 来源目录卡片中的主要操作按钮保持正常横向排版，不允许文字逐字竖排。
- 长 URL、来源 ID 和技术备注应允许换行，不得撑破卡片宽度。

## 6. 变更验收

每次主题或共享组件变更至少检查：

1. 聚合搜索：输入、选择器、按钮的尺寸和对齐。
2. 数据源管理：登录、来源目录卡片、编辑表单、状态提示。
3. 适配器管理：列表、状态标签、编辑表单和危险操作。
4. 窄屏布局：控件不溢出、按钮不被压成窄列。
5. 键盘操作：焦点可见、表单可提交；弹窗打开后焦点进入弹窗，Tab 不离开弹窗，Esc 可关闭且关闭后焦点返回触发位置。
